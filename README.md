# ft_irc — المشاكل اللي خاصك تصلح

---

## المشكلة العامة

الـ Parser والـ Dispatcher دابا تقادوا كاملين، ولكن فاش جينا نستيو الأوامر كاملين فـ Irssi، لقينا باللي كاينين مشاكل لوجيكية وأخطاء ف هندسة الميموري عندك ف الـ Backend. هما لي كايحبسوا الأوامر بحال `KICK` و`MODE` و`TOPIC` وكايديروا مشاكل ف البث وكايطردوا الناس دقة وحدة.

هاوماك 4 عيوب خاصك تراجعهم وتصلحهم بيدك ف ملفات الـ Server والـ Channel:

---

## 1 — مشكل الـ Pass-by-Value فـ كلاس Server

### شنو كاين

الدوال بحال `processChannelJoin` وباقي الدوال المساعدة ف كلاس `Server` كايستقبلوا أو كايرجعوا الـ `Client` بالـ **Pass-by-Value** عوض **Pass-by-Reference**.

### شنو كايوقع بسببه

فاش كادوز أوبجيكت بالـ Pass-by-Value، السيرفر كايصاوب **نسخة مؤقتة جديدة ف الـ Stack**. فاش كاتتحط الـ Pointer ديال هاد النسخة ف الـ Vectors (`_vClient` أو `_vOperator`)، ديك النسخة كاتموت غير ما تسالي الدالة. النتيجة:

- الـ Pointers لي مخزنين كايوليوا **Dangling Pointers** كايشيروا لبلاصة خاوية.
- فاش كانديروا `KICK` أو أي أمر، السيرفر ما كايتعرفش على الـ `Fd` الحقيقي وكايقول ديما "راك ماشي Operator" أو "ما كاينش فالشانل".

### شنو خاصك تدير

راجع الـ Signatures ديال الدوال ف السيرفر، وتأكد أن **كاع الدوال لي كاتهز أو كاترجع `Client` تخدم بـ `Client&` أو `Client*`** باش تحافظ على نفس عنوان الميموري الأصلي.

## 2 — مقلوبية خطوات الـ JOIN

### شنو كاين

الترتيب ديال خطوات الـ Lifecycle ف دالة الدخول للشانل **مقلوب** ف الـ Backend.

### شنو كايوقع بسببه

الكود كايدخل الكلينت للـ Vector ديال الشانل أولاً، وعاد موراها كايشيك بـ `isEmpty()` باش يعطيه صلاحية الآدمن. بما أن الكلينت تزاد ديجا، `isEmpty()` ديما كاتلقى الشانل عامر وكاترجع `false`. النتيجة:

- **أول مستخدم كايصاوب الشانل عمره ما كايولي Operator**.
- كاع الكلينتس كايتخزنوا كمستخدمين عاديين وماعندهمش الحق يسيرو الغرفة.

### شنو خاصك تدير

راجع لوجيك الدخول. خاصك **تشيك `isEmpty()` قبل ما تزيد الكلينت** للـ Vector، مو بعدها.

## 3 — غياب التخزين المركزي للشانلز فـ السيرفر

### شنو كاين

كلاس `Server` ما فيه مكان تخزين حقيقي وموحد (بحال `std::map`) كايجمع الشانلز كاملين. الدوال ديال البحث كانت كاترجع غير `NULL`. هادشي كان كايخلي كاع الكلينتس معزولين وكل واحد كايتكريا ليه شانل بوحدو ف بلاصة معزولة — **جوج ناس يجوينوا `#foo` كل واحد كايتعطاه شانل مختلف**.

### شنو خاصك تدير

كلاس `Server` خاصو يكون هو الـ **Single Source of Truth**. خاصك:

- تقاد التخزين ديال الشانلز وسط `std::map` نيت فـ السيرفر.
- تخلي دالة البحث والـ Creation تقلب وتخزن وسط هاد الـ Map.

هكا يلا دخلوا جوج ناس لنفس الشانل يتشاركوا نفس الأوبجيكت ف الميموري.

## 4 — التزيار فـ صيغة الـ Broadcast

### شنو كاين

الدالة `Channel::broadcast` كاتلصق ديما وبشكل إجباري الـ Prefix `:nick PRIVMSG #channel :` مع أي رسالة خارجة.

### شنو كايوقع بسببه

هاد التزيار كايفركع البروتوكول ديال IRC بالكامل. فاش كنبغيوا نبعثوا إشعار `JOIN` أو `KICK` أو تغيير `TOPIC`، الدالة كاتلصق معاهم `PRIVMSG` بزز، وهادشي كايخلي Irssi يتلف وميفهمش نوع الأمر.

### شنو خاصك تدير

رد الدالة `broadcast` تكون **Raw Forwarder** نقي — كاتشد الـ `string` كيفما عطيته ليها وتبعثه نيشان للـ Socket. وخلي الدوال الأخرى بحال `kickClient` و`ChangeTopic` هما لي يتكلفوا بفورمات الرسالة الكاملة قبل ما يعيطوا ليها.

## ملخص

| رقم | الملف | المشكل | الحل |
|---|---|---|---|
| 1 | `Server` | `Client` كيتدوز بالـ Value | بدلو كلو لـ `Client&` أو `Client*` |
| 2 | `Server` / `Channel` | `addClient` قبل `isEmpty` | دير `isEmpty` قبل `addClient` |
| 3 | `Server` | ما كاينش `std::map` للشانلز | زيد `std::map` وخلي السيرفر هو المرجع |
| 4 | `Channel` | `broadcast` كاتزيد PRIVMSG بزز | خليها Raw Forwarder فقط |
