الميموري عندك ف الـ Backend هما لي كايحبسو الأوامر (بحال KICK, MODE, TOPIC...) وكايديروا مشاكل ف البث ولا كايطردوا الناس دقة وحدة.  ها هما العيوب الـ 4 لي خاصك تدخل تراجعهم وتصلحهم بيدك ف ملفات الـ Server والـ Channel بلا ما نعطيك الكود واجد:  1. مشكل الـ Pass-by-Value ف كلاس الـ Serverالمشكل: ف الدالة processChannelJoin وباقي الدوال المساعدة ف كلاس الـ Server لي كاتخدم بالكلينت، كاينين دوال كايستقبلوا ولا كايرجعوا الكلينت بالـ Pass-by-Value ف بلاصة الـ Pass-by-Reference.  شنو كايوقع بسبابه: ف السي بلس بلس، فاش كادوز أوبجيكت بالـ Pass-by-Value، السيرفر كايصاوب نسخة مؤقتة جديدة ف الـ Stack. فاش كاتحط الـ Pointer ديال هاد النسخة ف الـ Vectors (_vClient ولا _vOperator)، ديك النسخة كاتموت غير كاتسالي الدالة. النتيجة هي أن الـ Pointers لي مخزنين عندك كايوليوا كايشيروا لبلاصة خاوية ف الميموري (Dangling Pointers)، داكشي علاش فاش كانديروا KICK ولا أي أمر، السيرفر ما كايتعرفش على الـ Fd ديال الكلينت الحقيقي وكايقول ليه ديما باللي نتا ماشي Operator ولا ما كاينش فالشانل!  المطلوب منك: راجع الـ Signatures ديال الدوال ف السيرفر، وتأكد أن كاع الدوال لي كاتهز ولا كاترجع Client تخدم بالـ References (Client&) ولا الـ Pointers (Client*) باش تحافظ على نفس عنوان الميموري الأصلي.  2. مقلوبية خطوات الـ JOIN (Order of Operations Bug)المشكل: الترتيب ديال خطوات الـ Lifecycle ف دالة الدخول للشانل مقلوب عندك ف الـ Backend.  شنو كايوقع بسبابه: الكود كايقوم بإدخال الكلينت للـ Vector ديال الشانل هو الأول، وعاد موراها كايشيك بـ isEmpty() واش الشانل خاوي باش يعطيه الصلاحية ديال الآدمن (addOperator). بما أن الكلينت تـزاد ديجا ف السطر لي قبل، الـ isEmpty() ديما كاتلقى الشانل عامر وكاترجع false. هادشي كايخلي أول مستخدم كايصاوب الشانل عمره ما كايولي Operator، وكاع الكلينتس كايتخزنوا كـ مستخدمين عاديين وماعندهمش الحق يسيرو الغرفة.  المطلوب منك: راجع اللوجيك ديال الدخول، وخاصك تشيك على الحالة ديال الشانل واش خاوي تماماً بـ isEmpty() قبل ما تدفع الكلينت وسط الـ Vector ديال المستخدمين.  3. غياب التخزين المركزي للشانلز ف السيرفر (Decoupled Memory Allocation)المشكل: الكلاس الكبير ديال الـ Server ما كانش فيه مكان تخزين حقيقي وموحد (بحال std::map) كايجمع الشانلز كاملين، والدوال ديال البحث كانت كاترجع غير قيمة وهمية بحال NULL. هادشي كان كايخلي كاع الكلينتس معزولين وكل واحد كايتكريا ليه شانل بوحدو ف بلاصة معزولة.  المطلوب منك: كلاس الـ Server خاصو يكون هو الـ Single Source of Truth. خاصك تـقاد التخزين ديال الشانلز وسط السيرفر نيت فـ std::map، وتخلّي الدالة ديال البحث والـ Creation تقلب وتخزن وسط هاد التخزين المركزي، باش يلا دخلوا جوج د الناس لنفس السمية يتشاركوا نيت نفس الأوبجيكت ف الميموري.  4. التزيار ف صيغة الـ Broadcast العامة (Broadcast Format Hardcoding)المشكل: الدالة Channel::broadcast كاتبها بحيث كاتلصق ديما وبشكل إجباري الـ Prefix ديال :nick PRIVMSG #channel : مع أي ميساج خارج.  شنو كايوقع بسبابه: هاد التزيار كايفركع البروتوكول ديال الـ IRC تماماً. فاش كنبغيوا نخدموا بالـ broadcast باش نصيفطوا إشعار ديال JOIN ولا KICK ولا تغيير TOPIC، الدالة كاتلصق معاهم PRIVMSG بزز، وهادشي كايخلي البرنامج ديال Irssi يتلف وميفهمش نوع الأمر.  المطلوب منك: رد الدالة broadcast
